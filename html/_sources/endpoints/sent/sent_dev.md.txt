# SENT Driver

**File:** `endpoints/sent/sent_dev.proto`

**Package:** `esb.sent`

SENT configuration, actions, queries, and notifications for RCP.

A SENT endpoint receives messages of the single edge nibble transmission (SENT) protocol (SAE J2716). A sensor sends
them periodically over a single wire, and the endpoint only listens. The client configures the endpoint with a
[`fldConfig`](#protogen.esb.sent.fldConfig) message, starts it with a command, and receives the messages in notifications.

## Message format

A SENT message is a sequence of pulses. Each pulse starts with a falling edge, stays low for 5 ticks, and is
measured from its falling edge to the next one. The tick time {math}`t_{tick}` is defined by the sensor. There is no tick
time parameter. The synchronization pulse, 56 ticks long, lets the receiver measure the tick time. Each nibble pulse
carries a four-bit value {math}`N` in its length of 12 + {math}`N` ticks: the first nibble is the status, then up to six data
nibbles follow, and the last one is the cyclic redundancy check (CRC). An optional pause pulse can be used to give
all messages the same length.

![](../../../../../sw_proto_rcp/figures/endpoints/timingSentFrame.svg)

## Streaming

The client starts and stops the reception with a command. The endpoint collects the received messages in a buffer
and flushes it to the client in notifications when it is full, see [`fldNotif.data`](#protogen.esb.fldNotif.data). The format of the data
in the buffer is server-dependent. Refer to the datasheet.

## Example

To receive messages with one status nibble, six data nibbles, and one CRC nibble from a sensor that sends a pause
pulse:

```text
seq: 1
dir { config { hndl: 9  sent { frameLength: 8  expectPause: true  bufferSizeBytes: 256 } } }
dir { action { hndl: 9  sent { op: opStart } } }
```
