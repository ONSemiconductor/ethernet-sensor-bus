# Code generators

A *code generator* reads the `.proto` files and writes a library for one programming language: message types, encoders, and decoders. Compatible generators share the protobuf wire format, but the library does not implement the behavior of RCP. The bytes of one message can differ, see [Protobuf encoding](protobuf.md).

A generator has to support proto3 with `optional` fields, `oneof` groups, `repeated` fields, nested messages, `reserved` field numbers, and imports between files in subfolders.

A server also needs the directive validation described in [Messages](messages.md). A decoder that silently skips unknown fields or keeps only the last `oneof` member loses information needed for those checks. Check it during decoding, before any operation executes.

## The Protocol Buffers compiler

`protoc`, the Protocol Buffers compiler, parses and checks the `.proto` files and runs the generators. The option `--<language>_out=<directory>` selects a built-in generator. A generator that is a separate plugin program `protoc-gen-<name>` is selected with `--<name>_out`.

```text
protoc -I protocol --python_out=generated/python \
    $(find protocol -name '*.proto')
```

## Generators from Google

The built-in generators of `protoc` are made for general-purpose computers. The code that they write needs the runtime library of Google for the language, in a version that is compatible with `protoc`, see [Cross-Version Runtime Guarantee](https://protobuf.dev/support/cross-version-runtime-guarantee/), and the messages are objects that the library allocates dynamically.

The following Python script uses the code that `--python_out` generated and the package `protobuf` to build and encode the directive that queries the identity of an RCP server. Run it with `generated/python` on the `PYTHONPATH`:

```python
import rcp_pb2
from server import rcp_dev_pb2

directive = rcp_pb2.msgDirective(seq=1)
directive.dir.add().query.rcp = rcp_dev_pb2.qryIdentity
data = directive.SerializeToString()
# data: 0D 01 00 00 00 12 04 1A 02 10 0A
```

## Generators for small systems

The firmware of a microcontroller often has no room for a general-purpose runtime and cannot allocate memory dynamically. Other projects write the code for these targets, and the list of [third-party add-ons](https://github.com/protocolbuffers/protobuf/blob/main/docs/third_party.md) on the Protocol Buffers website names many. Examples are [Nanopb](https://koti.kapsi.fi/jpa/nanopb/) and [protobuf-c](https://github.com/protobuf-c/protobuf-c) for C, and [EmbeddedProto](https://embeddedproto.com/) for C++. Check that the generator supports `optional` fields.
