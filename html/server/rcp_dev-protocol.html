Protocol

Messages

fldConfig

Message esb.rcp.dev.fldConfig

Container of all RCP server configurations.

Fields

  • cfg — oneof

    • server — core.fldServerConfig
      RCP server configuration (e.g., DID).

    • ptp — ptp.fldConfig
      PTP protocol configuration.

    • plca — plca.fldConfig
      PLCA configuration.

    • pins — pins.fldConfig
      RCP pins configuration.

    • net — net.fldConfig
      Network configuration.

    • phyReg — net.fldPhyReg
      PHY registers configuration.

    • vendor — vendor.fldConfig
      Vendor-specific configuration.

    • client — net.fldClientConfig
      Client configuration.

fldCmd

Message esb.rcp.dev.fldCmd

Container for all RCP server commands.

Fields

  • op — enCmdOperation
    Management operation to perform.

  • param — oneof
    Command-specific parameters.

    • topDisc — tpd.fldCmd
      Topology discovery (opTopologyDiscovery).

    • phyReg — net.fldPhyReg
      PHY registers access (opManagePhyRegisters).

    • time — fldTstamp
      PTP time set (opSetPtpTime).

    • nvmOp — core.fldNvmOperation
      NVM operation parameters.

fldCmdResult

Message esb.rcp.dev.fldCmdResult

Container for results of RCP commands.

Fields

  • res — oneof

    • topDiscResult — tpd.fldCmdResult
      Topology discovery result.

    • phyData — net.fldPhyData
      PHY register data.

fldQueryResult

Message esb.rcp.dev.fldQueryResult

Container for the results of all queries of the RCP server.

Fields

  • rep — oneof

    • identity — info.fldIdentity
      Reply to qryIdentity.

    • capabilities — info.fldCapabilities
      Reply to qryCapabilities.

    • interfaces — info.fldInterfaces
      Reply to qryInterfaces.

    • pins — pins.fldDescriptors
      Reply to qryPins.

    • server — core.fldServerStatus
      Reply to qryServerStatus.

    • net — net.fldStatus
      Reply to qryNetStatus.

    • ptp — ptp.fldStatus
      Reply to qryPtpStatus.

    • plca — plca.fldStatus
      Reply to qryPlcaStatus.

    • scheduler — core.fldSchedulerStatus
      Reply to qrySchedulerStatus.

    • nvm — core.fldNvmStatus
      Reply to qryNvmStatus.

    • vendor — vendor.fldStatus
      Reply to qryVendorStatus.

    • client — net.fldClientStatus
      Reply to qryClientStatus.

Enumerations

enCmdOperation

Enumeration esb.rcp.dev.enCmdOperation

RCP server management operations.

  • opNone — This operation is a no-op and does not alter the state of the RCP server. However, it counts as a network watchdog refresh message, so the client can use it as a keep-alive message.

  • opResetDevice — Reset the RCP server. If set, the RCP server reboots, clearing all dynamic configuration and resetting all internal states and variables.

  • opSaveConfig — Saves the current RCP configuration into non-volatile memory.

  • opRestoreConfig — Restores the last saved RCP configuration from non-volatile memory. If the operation fails, the current configuration does not change.

  • opSleep — Commands the RCP server to enter deep-sleep mode. In deep-sleep mode, all RCP server functions are switched off, and all dynamic configuration and states are lost. A portion of the RCP server stays powered to detect wakeup signals from local sources or from the Ethernet bus. The wakeup signal triggers a full (re)boot of the server.

  • opRestoreFactoryConfig — Forces the RCP server to erase the NVM content and reboot. The default HW configuration is then applied when the system comes back to life.

  • opClearPwron — This command clears the core.fldServerStatus.pwrOn flag in the RCP server status. See core.fldServerStatus for more information.

  • opTopologyDiscovery — Commands the RCP server to initiate topology discovery if the HW supports it. 10BASE-T1S PHYs can provide this feature.

  • opManagePhyRegisters — Initiates an MDIO read or write operation to configure the PHY. See also net.fldMdioConfig.

  • opSetPtpTime
    Sets the value for the internal PTP timer. Setting the PTP timer with this command can yield an error of several milliseconds, depending on the client latency and the network conditions.

    Warning

    Setting the PTP timer with this method can make scheduled actions fail or be delayed for a long time, depending on the direction of the time shift.

  • opClearStoredActions — Clears all actions that are currently stored in the NVM. It does not affect actions loaded into volatile memory.

  • opEnterSilent
    Enter silent mode. Features such as 10BASE-T1S topology discovery or cable fault detection need the line to be silent.

    Note

    The server sends back a confirmation once it has entered silent mode, unless suppressed explicitly.

  • opExitSilent — Leave silent mode. If the server was not in silent mode, this command is ignored.

  • opEnterFailsafe — Forces the RCP server into fail-safe mode.

  • opCancelAllActions — Resets the RCP server scheduler, clearing all pending scheduled actions. This includes actions with a repetition count that still have pending executions. A running action always completes.

  • opGlobalWakeup
    Makes the PHY send a global wakeup signal on the Ethernet line to wake up all sleeping nodes on the same network segment.

    Note

    Ethernet switches and PHYs can be programmed to propagate the wakeup signal further.

  • opLoadStoredActions
    Loads the stored actions from non-volatile memory. Existing actions loaded in RAM are not canceled.

    Warning

    Executing this operation multiple times causes actions to be loaded multiple times into RAM.

  • opManageUserData — Access the user-dedicated NVM, i.e., write or read user data to/from non-volatile memory. See core.fldNvmOperation.

enQuery

Enumeration esb.rcp.dev.enQuery

Queries of the RCP server. Queries indicated with [M] are mandatory, meaning that ESB-compliant servers implement them. Queries marked with [H] are mandatory if the specific HW supports it. Queries marked with [O] are optional to implement.

  • qryServerConfig — [M] Get current RCP server configuration.

  • qryPtpConfig — [H] Get current PTP protocol configuration.

  • qryPlcaConfig — [H] Get current PLCA configuration.

  • qryPinConfig — [M] Get current RCP pins configuration.

  • qryNetConfig — [M] Get current network configuration.

  • qryRegConfig — [H] Get default register configuration.

  • qryIdentity — [M] Get basic server information (vendor, serial, …).

  • qryCapabilities — [O] Get server capabilities (supported features).

  • qryInterfaces — [O] Retrieve a list of supported endpoints (SPI, I2C, …).

  • qryPins — [O] Retrieve a list of pins and supported functions.

  • qryServerStatus — [H] Get state of the server, whether fail-safe mode was activated or not.

  • qryNetStatus — [O] Get current network status.

  • qryPtpStatus — [H] Get current PTP protocol status.

  • qryPlcaStatus — [H] Get current PLCA status.

  • qrySchedulerStatus — [M] Get RCP Scheduler status.

  • qryNvmStatus — [H] Get RCP NVM status.

  • qryVendorStatus — [O] Get current vendor-specific status.

  • qryClientStatus — [M] Get current client status.
