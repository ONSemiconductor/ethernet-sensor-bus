PDM Driver

File: endpoints/pdm/pdm_dev.proto

Package: esb.pdm

PDM configuration, actions, queries, and notifications for RCP.

A PDM endpoint receives a pulse-density modulation (PDM) stream, for example from a digital microphone. The endpoint drives the clock CLK and samples the data line DATA, see the pin functions rcp.pins.enPinFuncPdm.

Principle

A PDM stream is a one-bit stream with a high bit rate. The amplitude of the signal is encoded in the density of the 1 bits: many 1 bits stand for a large positive value, many 0 bits for a large negative value. Converting the stream to audio samples with a lower rate requires filtering and decimation. This conversion is not part of the protocol. The endpoint streams the sampled bits to the client.

Clock and sampling edge

The endpoint takes over DATA on the rising edge, on the falling edge, or on both edges of the clock. With both edges, two bits are received per clock period, so the bit rate is twice the clock speed.

Streaming

The client starts and stops the stream with a command. The endpoint collects the sampled bits in a buffer and delivers them to the client in notifications, see fldNotif.data.

Example

To record a PDM microphone with a 3.072 MHz clock, sampled on the rising edge:

seq: 1
dir { config { hndl: 6  pdm { speedHz: 3072000  samplingEdge: samplingRising  bufferSizeBytes: 1024 } } }
dir { action { hndl: 6  pdm { op: opStart } } }
