fldConfig

Message esb.fldConfig

Container for all configuration operations.

Fields

  • hndl — uint32
    Unique non-zero handle of the endpoint, or 0 for the RCP server itself.

  • dev — oneof
    Configuration matching the type of the endpoint at hndl.

    • rcp — rcp.dev.fldConfig
      Configuration of the RCP server itself.

    • gpio — gpio.fldConfig
      Configuration of a GPIO controller.

    • i2c — i2c.fldConfig
      Configuration of an I2C controller.

    • spi — spi.fldConfig
      Configuration of a SPI controller.

    • uart — uart.fldConfig
      Configuration of a UART controller.

    • pcm — pcm.fldConfig
      Configuration of a PCM audio controller.

    • pdm — pdm.fldConfig
      Configuration of a PDM controller.

    • adc — adc.fldConfig
      Configuration of an ADC controller.

    • sent — sent.fldConfig
      Configuration of a SENT controller.

    • lin — lin.fldConfig
      Configuration of a LIN controller.

    • pwm — pwm.fldConfig
      Configuration of a PWM controller.

fldActionTimed

Message esb.fldActionTimed

Configuration of timed actions.

Fields

  • start — oneof
    Presentation time of the first execution. If absent, the action runs as soon as the endpoint is free.

    Note

    The granularity and precision of the PTP timer are implementation-specific. Refer to the datasheet of the server for details.

    • ptime — fldTstamp
      Absolute time: the operation is executed when the internal PTP timer crosses this presentation time.

    • offset — fldTstamp
      Relative time: the RCP server captures the precise time at which the directive is received from the network, then schedules the operation to be executed at that time plus this offset.

  • period — fldTstamp
    Repeat interval of this timed action. It is only used if the fldAction.repeatCount field is greater than 0. The RCP server then calculates each subsequent presentation time by adding this interval to the previous presentation time. Delays in execution and duration of the action do not affect the interval. The periodAdjNs field can change the interval after every execution.

  • hardDeadline — bool
    Decides whether a late action is dropped or executed. An action is late if it cannot be scheduled at the specified time. This happens if ptime lies in the past, or if the endpoint is busy executing other operations at the desired scheduling time.

    If set to true, a late action is not executed. Its result code is actTooLate, an error code.

    If set to false (or not set), a late action is always executed, even if the required deadline cannot be met. However, in this case its result code is actDelayed, a warning code, if execution succeeds. A failed execution returns its error instead.

    Note

    This field does not guarantee that the RCP server sends a reply. Whether and when the result code is reported depends on the fldAction.replyMode of the action. The warning actDelayed is treated as a successful execution, so actReplyOnError reports actTooLate but not actDelayed. Reply modes that report only on the last action of a series can defer the result.

  • periodAdjNs — sint32
    If set, the specified adjustment time in nanoseconds is added/subtracted from the repeating period after each time the action is re-scheduled. This allows creating sequences of operations that repeat faster or slower in a linear fashion.

    Note

    This option is only used in conjunction with the period parameter. If this one is not specified, the periodAdjNs field is ignored.

fldActionEvent

Message esb.fldActionEvent

Configuration for event-triggered actions.

Fields

  • events — repeated uint32
    Actions can optionally be triggered on specific events. If the events array is not empty, the action is executed when the RCP server asserts any of the events contained therein. The list of available events and associated IDs is implementation-specific. Refer to the datasheet of the server for details.

  • delay — fldTstamp
    If set, this optional parameter defines the delay in PTP time format between the time the event was asserted and the time the action is scheduled.

fldActionDependent

Message esb.fldActionDependent

Configuration for an action triggered by the completion of a parent action. If the parent is removed while this action is waiting for its completion, this action is removed without a notification or an action result. An already-triggered execution, including its delay, completes under fldAction.replyMode but does not repeat.

Fields

  • tag — uint32
    Tag of the parent action to wait for. The tag 0 refers to the previously queued action. See fldAction.tag for how a tag is resolved.

  • trigType — enActionDependentType
    The trigger type (see enActionDependentType).

  • delay — fldTstamp
    If set, the actual execution of the action is further delayed by the specified amount of time after the completion of the parent action.

fldAction

Message esb.fldAction

Container for an action that an endpoint or the RCP server executes.

Fields

  • trigger — oneof
    Selects when the action runs. Without a trigger, it runs as soon as the endpoint is free. An action without a trigger and with repeatCount equal to 0 is synchronous, unless rcp.core.fldServerConfig.syncActionsEnable is false. Its execution result is returned in the reply to the directive. All other actions are asynchronous, including one with an empty timed message. A queued asynchronous action returns actPending. Its execution results follow in unsolicited reports, subject to replyMode.

    • timed — fldActionTimed
      Execute at a specific time, as defined by fldActionTimed.

    • event — fldActionEvent
      Execute upon the assertion of one or more events, as defined by fldActionEvent.

    • action — fldActionDependent
      Execute after the completion of another action, as defined by fldActionDependent.

    • bind — uint32
      Execute concurrently with the action that has the specified tag (see tag). The tag 0 refers to the previously queued action. Bound actions refer to different endpoints (handles). Otherwise, the RCP server rejects the action.

  • repeatCount — uint32
    If set to a non-zero value, the RCP server automatically re-schedules the operation based on the specified trigger type. The total number of times the action is scheduled is repeatCount + 1. If repeatCount is set to 0, or not set (default), the action is executed once. If repeatCount is set to its maximum value (0xffffffff), the action is re-scheduled indefinitely, or until canceled.

    Note

    Setting this parameter to a non-zero value makes the action asynchronous regardless of the trigger type.

  • replyMode — enActionReplyMode
    Reply mode for this action, see enActionReplyMode. If the action is synchronous, this parameter is ignored. For the definition of synchronous actions, see the trigger field documentation.

  • failsafe — bool
    If set, the action is executed only if the RCP server is in fail-safe mode. Fail-safe mode can be triggered by the network watchdog or other implementation-specific conditions (refer to the datasheet of the server). For asynchronous operations (see the trigger field documentation), this parameter adds fail-safe mode as an additional condition for scheduling. For synchronous operations, if this parameter is set and the system is not currently in fail-safe mode, the action is rejected with the actFailsafeError error code. If this parameter is not set, the action is rejected if the system is currently in fail-safe mode. This feature can be useful for implementing functional safety and safe operation of the server in case, for example, of loss of network connectivity.

  • storeToNvm — bool
    If set, the action is saved in non-volatile memory and loaded on server POR or reboot.

    Warning

    Actions stored to NVM are not loaded into RAM at the same time. The command rcp.dev.opLoadStoredActions loads all saved actions.

  • tag — uint32
    Optional label that the client gives to the action. It does not have to be unique: several actions can carry the same tag, and 0 means that the action has no tag. The tag is how other operations refer to this action:

    • the triggers action (dependent) and bind of later actions

    • the cancel operation by tag, see fldActionCancel.tag

    When more than one live action carries the same tag, a trigger refers to the first one found, while canceling by tag cancels all of them. In contrast, the RCP server assigns every queued action a unique fldActionResult.uid, which the client only learns from the acknowledgement. It refers to exactly one action, see fldActionCancel.uid.

  • hndl — uint32
    Handle of the endpoint, or 0 for the RCP server itself. Endpoint handles are unique and non-zero. The datasheet of the server and the query rcp.dev.qryInterfaces list the endpoints with their handles and types.

  • dev — oneof
    The endpoint-specific command.

    • rcp — rcp.dev.fldCmd
      Commands for RCP functionality.

    • gpio — gpio.fldCmd
      Commands for GPIO interfaces.

    • spi — spi.fldCmd
      Commands for SPI interfaces.

    • i2c — i2c.fldCmd
      Commands for I2C interfaces.

    • pwm — pwm.fldCmd
      Commands for PWM interfaces.

    • pcm — pcm.fldCmd
      Commands for PCM audio interfaces.

    • uart — uart.fldCmd
      Commands for UART interfaces.

    • pdm — pdm.fldCmd
      Commands for PDM interfaces.

    • adc — adc.fldCmd
      Commands for ADC interfaces.

    • sent — sent.fldCmd
      Commands for SENT interfaces.

    • lin — lin.fldCmd
      Commands for LIN interfaces.

fldActionResult

Message esb.fldActionResult

Result of an action. The RCP server returns it as a direct reply to an action (fldAction). Such a reply reports either the execution of a synchronous action or the scheduling of an asynchronous action. The server also returns it when an asynchronous action has run. Such an unsolicited result reports the execution.

Fields

  • code — enActionResult
    Result code of the action.

  • tag — optional uint32
    The tag that the client gave in fldAction.tag, only present if it was not zero. It is not necessarily unique, use the uid to tell actions apart.

  • seq — optional fixed32
    The RCP server generates a sequence number for each reply of an asynchronous action (see uid). The number increases by one with each reply. Each action has its own series, so the number is not globally unique. The client can use it to detect missing or misordered replies of each action independently.

  • time — optional fldTstamp
    Optional timestamp in PTP format that the RCP server captures when it executes specific types of actions (e.g., GPIO capture). The RCP server can also set it if an event triggered the action or if the action was late.

  • triggerId — optional uint32
    For the result of an event-triggered action, this field specifies the trigger ID that became active.

    Warning

    If multiple events trigger the action at the same time, only the one with the highest priority, i.e., the lowest event identifier, is reported as triggerId.

  • res — oneof
    Endpoint-specific reply data.

    • gpio — uint32
      Result generated by GPIOs.

    • data — bytes
      Generic binary data (multiple endpoints).

    • rcp — rcp.dev.fldCmdResult
      Result of RCP commands.

  • uid — optional uint32
    Unique non-zero ID generated by the RCP server for every queued action. It is included in the acknowledgement of the action and in every result of that action. Live actions never share a uid. Unlike the tag, which the client chooses, the client only learns it from the acknowledgement.

fldQuery

Message esb.fldQuery

Container for a query of the RCP server or of an endpoint.

Fields

  • hndl — uint32
    Handle of the endpoint to query, or 0 for the RCP server itself. Endpoint handles are unique and non-zero. The datasheet of the server and the query rcp.dev.qryInterfaces list the endpoints with their handles and types.

  • qry — oneof
    The RCP server supports synchronous queries to retrieve static or dynamic information about the RCP server itself or one of its endpoints. If none of the options is selected and hndl is non-zero, the query returns the configuration of the specified endpoint.

    • rcp — rcp.dev.enQuery
      Query of the RCP server itself.

    • ep — enEndpointQuery
      Query of an endpoint.

fldQueryResult

Message esb.fldQueryResult

Container for the result of a query.

Fields

  • code — enQueryResult
    Return code of the query.

  • res — oneof
    Content of the specific query reply.

    Note

    config does not use the field fldConfig.rcp. To retrieve the configuration of the RCP server, use the individual queries and the field rcp of this message.

    • rcp — rcp.dev.fldQueryResult
      Reply to RCP server queries.

    • config — fldConfig
      Reply to endpoints config queries.

    • epInfo — fldEndpointNotifInfo
      Reply to endpoint status query.

fldNotif

Message esb.fldNotif

Notifications sent by the server, including endpoint events and received stream data. Each endpoint sends its notifications only to its notification owner, identified by fldEndpointNotifInfo. This message also carries directive-decoding errors.

Fields

  • code — enNotifResult
    Result code of the notification.

  • hndl — uint32
    Endpoint that generated the notification.

  • seq — fixed32
    The RCP server generates a sequence number for each notification of an endpoint. The number increases by one with each notification. Each endpoint has its own series, so the number is not globally unique. The client can use it to detect missing or misordered notifications of each endpoint independently.

  • time — optional fldTstamp
    Optional timestamp in PTP format, captured by the RCP server when triggering specific types of notifications (e.g., GPIO capture).

  • ntf — oneof
    Data supplied by the notifying endpoint.

    • gpio — gpio.fldNotif
      GPIO change status notification.

    • data — bytes
      Endpoint bytes (streaming).

    • adc — adc.fldNotif
      ADC specific notifications.

fldActionCancel

Message esb.fldActionCancel

Selects live actions to cancel, either by tag or by uid. An action is live while scheduled or running. A scheduled action is removed. A running action completes its current execution without further repetitions.

Fields

  • by — oneof
    Identifier used to select live actions.

    • tag — uint32
      Cancel all live actions that have this tag, see fldAction.tag.

    • uid — uint32
      Cancel the action that has this uid, see fldActionResult.uid.

fldOperation

Message esb.fldOperation

One operation of a directive.

Fields

  • deviceIdMask — optional uint32
    Optional mask to select which RCP servers execute the operation. If not set, all receiving RCP servers execute the operation. If set, the receiving RCP server executes the operation only if the bitwise AND of its own DID and the mask is not zero. All other RCP servers receiving the directive ignore this operation and add no result for it to the report. For an example, see the page Core Operations. This feature is useful when using broadcast and multicast messages on the network containing operations for multiple RCP servers. This allows the client to save bandwidth and reduce latency while keeping strict control over which server does what. The DID is set with rcp.core.fldServerConfig.did.

  • op — oneof
    Selects the operation type.

    • action — fldAction
      Action to perform.

    • query — fldQuery
      Query to perform.

    • config — fldConfig
      Configuration to apply.

    • cancel — fldActionCancel
      Actions to cancel.

fldOperationResult

Message esb.fldOperationResult

Container for the result of an operation. It is a direct response to an operation, an unsolicited action result, or a notification.

Fields

  • res — oneof

    • action — fldActionResult
      Result of an action.

    • query — fldQueryResult
      Result of a query.

    • config — enConfigResult
      Result of a configuration.

    • cancel — enAclResult
      Result of an action cancel.

    • notif — fldNotif
      Unsolicited notification or directive-decoding error.

msgDirective

Message esb.msgDirective

Top-level message from the client to the RCP server. The server decodes the whole message before handling its operations. It rejects the whole directive for a decoding error. No operation is executed, and the reply contains one fldNotif describing the error.

Fields

  • seq — fixed32
    Sequence number used to correlate directives and reports. A non-zero value is echoed in msgReport.seq. 0 (default) suppresses the normal reply, but not unsolicited reports or the error report for a directive rejected during decoding. The number does not suppress duplicate execution. Receiving the same directive again can execute it again.

  • dir — repeated fldOperation
    Operations handled in list order. An asynchronous action is queued at its position, not awaited. An operation error neither rolls back earlier operations nor prevents later operations from being handled. If a reply is requested, it contains one result per operation in the same order, except for an operation ignored because of fldOperation.deviceIdMask.

msgReport

Message esb.msgReport

Top-level message from the RCP server to the client.

Fields

  • seq — fixed32
    Echoes msgDirective.seq in a reply. In an unsolicited report, it is 0. For a directive rejected during decoding, it carries the directive’s sequence number only if the server read it before detecting the error. Otherwise, it is 0.

  • res — repeated fldOperationResult
    A reply contains one result per operation, in directive order, except for operations ignored because of fldOperation.deviceIdMask. A directive rejected during decoding produces one fldNotif instead. An unsolicited report contains asynchronous action results or endpoint notifications.

msgRcp

Message esb.msgRcp

Combination of the top-level messages msgDirective and msgReport. Neither side sends this message. Tools such as Wireshark use it to decode the messages of both directions, so the field set of msgRcp is the union of the fields of the two messages.

Note

The three messages use identical field numbers, so that Wireshark decodes them properly.

A client could use this message as a top-level message and omit the res or the dir field depending on the direction, but it should use the dedicated messages msgDirective and msgReport. The encoders and decoders inside the RCP server never use this message.

Fields

  • seq — fixed32
    The interpretation depends on the direction.

  • dir — repeated fldOperation
    List of operations to perform.

  • res — repeated fldOperationResult
    List of operation results.

Enumerations

enActionDependentType

Enumeration esb.enActionDependentType

Actions can optionally be triggered on completion of other actions. This allows, for example, defining daisy chains of timed operations to be executed as a reaction to specific events, in sequence.

  • actDepDefault — Execute as soon as the parent action finishes, regardless of its result code.

  • actDepSuccess — Execute only if the parent action succeeded: actSuccess or a warning such as actDelayed.

  • actDepError — Execute only if the parent action failed, i.e., its result code is an error.

enActionReplyMode

Enumeration esb.enActionReplyMode

Selects which execution results of an asynchronous action are sent in unsolicited reports. It does not affect the reply to the directive, which is controlled by msgDirective.seq. Warnings, including actDelayed, count as success rather than an error.

  • actReplyDefault — Report every execution.

  • actReplyNever — Report no executions.

  • actReplyOnError — Report only executions that fail.

  • actReplyOnLast — Report only the last execution of this action.

  • actReplyOnErrorOrLast — Report executions that fail and the last execution of this action.

enActionResult

Enumeration esb.enActionResult

Global enum for action results.

  • actSuccess — Action was successfully executed.

  • actPending — Action has been successfully scheduled.

  • actDelayed — Action was successful but executed past its due time.

  • actTooLate — Action was not executed because it missed its hard deadline.

  • actNoResources — Not enough server resources to perform the action.

  • actInvalidParam — A parameter value is invalid or out of range, or a combination of parameters violates the constraints of the requested operation.

  • actNotSupported — The requested operation or feature is not supported by this server.

  • actFailsafeError — Operating mode mismatch for the synchronous operation.

  • actInternalError — Unspecified internal error.

  • actCmdFailed — The execution of the command associated with the action failed.

  • actEndpointNotEnabled — Action failed because the endpoint is not enabled.

  • actTimeoutError — Action failed because the execution of the action timed out.

  • actCsumError — Action failed because of an invalid checksum.

  • actIOError — Action failed because of a hardware/bus error.

  • actStreamNotStarted — Action failed because the stream is not started.

  • actStreamAlreadyStarted — Action failed because the stream is already started.

  • actNvmNotPresent — Unable to access NVM because it is not present.

enQueryResult

Enumeration esb.enQueryResult

Global enum for query result code.

  • qrySuccess — Query was successful.

  • qryUnknownDevice — The specified handle is invalid.

  • qryInvalidParam — A parameter value is invalid or out of range, or a combination of parameters violates the constraints of the requested operation.

  • qryInternalError — Unspecified internal error.

  • qryEndpointNotEnabled — The query targets an endpoint that is not enabled.

  • qryNotSupported — The requested operation or feature is not supported by this server.

enNotifResult

Enumeration esb.enNotifResult

Result codes for endpoint notifications and directive decoding errors.

  • ntfSuccess — Notification was successful.

  • ntfIOError — Hardware/bus error.

  • ntfBufferOverrun — Buffer overrun occurred.

  • ntfProtocolError — The server could not decode the received message.

  • ntfProtocolTooLarge — The received message exceeds a limit of the server.

  • ntfProtocolUnsupported — The received message has an unknown field or several members of a oneof.

  • ntfInternalError — Unspecified internal error.

  • ntfFlushed — Endpoint was flushed (e.g., UART break).

  • ntfCsumError — Checksum error (e.g., UART parity error).

  • ntfFrameError — Frame error (e.g., UART framing error).

  • ntfOutOfMemory — Out of memory error.

enConfigResult

Enumeration esb.enConfigResult

Global enum for configuration result.

  • cfgSuccess — Configuration was successful (default).

  • cfgParamAdjusted — Configuration was successful, but some parameters were adjusted by the server.

  • cfgNotSupported — The requested operation or feature is not supported by this server.

  • cfgInvalidParam — A parameter value is invalid or out of range, or a combination of parameters violates the constraints of the requested operation.

  • cfgInternalError — Unspecified internal error.

  • cfgBusy — Server is busy and cannot accept the configuration at the moment.

  • cfgNotAllowed — Configuration not allowed for the item being configured because it is read-only.

enAclResult

Enumeration esb.enAclResult

Global enum for action cancel result.

  • aclSuccess — Action cancel operation was successful.

  • aclPending — Action cancel operation was successful, but the action was already in progress.

  • aclNotFound — Action cancel operation failed because the action was not found.

  • aclInternalError — Unspecified internal error.
