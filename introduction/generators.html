Code generators

A code generator reads the .proto files and writes a library for one programming language, consisting of message types, encoders, and decoders.

The Protocol Buffers compiler

protoc, the Protocol Buffers compiler, parses and checks the .proto files and runs the generators. The option --<language>_out=<directory> selects a built-in generator, and --<name>_out selects a plugin, i.e., a separate program named protoc-gen-<name>.

protoc -I protocol --python_out=generated/python \
    $(find protocol -name '*.proto')

Generators from Google

The built-in generators of protoc target general-purpose computers. The generated code needs the Google runtime library for the language, in a version compatible with protoc (see Cross-Version Runtime Guarantee), and the library allocates the messages dynamically.

The following Python script uses the code generated by --python_out and the protobuf package to build and encode the directive that queries the identity of an RCP server. It requires generated/python on the PYTHONPATH:

import rcp_pb2
from server import rcp_dev_pb2

directive = rcp_pb2.msgDirective(seq=1)
directive.dir.add().query.rcp = rcp_dev_pb2.qryIdentity
data = directive.SerializeToString()
# data: 0D 01 00 00 00 12 04 1A 02 10 0A

Generators for small systems

The firmware of a microcontroller often has no room for a general-purpose runtime and cannot allocate memory dynamically. Other projects provide generators for such targets, and the list of third-party add-ons on the Protocol Buffers website names many, e.g., Nanopb and protobuf-c for C and EmbeddedProto for C++. Verify that the generator supports optional fields.
